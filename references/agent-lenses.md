# Agent／LLM 面试维度

用于简历涉及 Agent、RAG、LLM 或模型部署时选择问题。问题须锚定实际主张或明确标出的岗位情景；未出现的技术不自动归入候选人的经历。

## 按简历线索选择

| 简历线索 | 一面：实现与事实 | 二面：约束与设计 | 负责人面：判断与价值 |
| --- | --- | --- | --- |
| Agent／任务规划 | 一次请求怎么识别、拆分、排序、执行和结束；谁决定调用模型或工具 | 步骤成功判定；超时、重试、重新规划与终止；中断恢复；长任务 | 业务是否需要 Agent；如何划定自动化边界；独立交付目标 |
| Skill／工具调用 | Skill 的内容、触发与执行关系；工具注册、Schema、输入输出、失败返回 | 只读与写入权限；高风险审批；参数校验、沙箱、外部副作用、重复执行 | 如何挑选优先自动化的动作；效率收益与风险如何验收 |
| Memory | 存什么、何时写入、长短期划分、存储与召回；数据膨胀 | 生命周期、冲突与过期；多用户隔离；错误记忆修正；检索质量 | 为什么值得引入记忆；如何证明持续使用带来收益 |
| Context／压缩 | 窗口与实际使用量；触发阈值、保留内容、压缩前后效果 | 工具结果与长历史如何管理；关键信息丢失如何发现、恢复和回归验证 | 效果、延迟与成本之间如何决策 |
| RAG／知识库 | 数据来源、切分、索引、召回、排序、引用与更新；真实失败案例 | 检索与生成分别评估；权限过滤、过期知识、无答案、增量更新 | 为什么选 RAG；何时改检索、模型或业务流程；收益指标 |
| Coding Agent | 大代码库如何构建 Code Context；向量、关键词、AST、调用链的实际角色 | 文件修改与命令执行边界；执行隔离、测试、失败恢复、重复执行 | 相对已有工具的业务差异；如何评价任务完成质量 |
| 模型选型／成本 | 候选模型、测试集、选择依据；输入输出 Token、缓存、多轮与重试成本 | 路由、配额、并发、速率限制、降级；质量与成本的比较 | 模型升级后什么能力值得保留或删除；单位业务收益 |
| 评测／优化 | 数据集来源、样本、指标、基线、错误分类与改进证据 | 离线与线上差异；回归、数据泄漏、版本对比、发布和回滚 | 哪些指标代表业务价值；改善是否足以支持继续投入 |
| 多 Agent／Harness／框架 | 为什么需要多个 Agent；职责、交接、状态与框架承担的工作 | 协作成本、循环与冲突、失败传播、可观测性；单 Agent 替代方案 | 复杂度是否值得；何时减少框架或 Agent 数量 |
| 微调／模型部署 | 为什么不先改数据或提示；训练目标、数据划分、部署路径 | 资源与容量、量化取舍、吞吐和延迟、异常与版本恢复 | 投入是否优于购买 API；质量与成本收益如何证明 |

## 连续追问示例

以下是练习题设计示例，不是某公司的真实题目。

### 一面：还原过去

主张：“做了上下文压缩。”

1. 哪一次任务让你发现需要压缩？当时 Context 包含什么？
2. 触发条件是什么，为什么这样定？
3. 保留、舍弃哪些信息，压缩结果如何进入下一次模型调用？
4. 关键约束被压掉时，结果怎样变错；你如何发现与处理？
5. 用什么样本和指标证明压缩后效果与成本可以接受？哪部分由你负责？

判断依据：过程与状态能否还原，阈值有无依据，失败与验证是否具体。只有做过相关工作才把回答写成既有经历。

### 二面：改变约束

场景：“一个执行十分钟、会多次调用工具的任务。”

1. 先说明最小执行流程和每个步骤的状态。
2. 第六步服务重启，需要保存什么才能继续？
3. 如果工具已经修改文件，但成功状态尚未保存，恢复时会发生什么？
4. 工具连续失败，重试、重规划和终止如何选择？
5. 同时有一百人使用时，如何限制资源与费用？
6. 更换模型或规划策略后，如何比较质量、延迟和成本？

判断依据：边界、副作用、恢复一致性、约束和验证。场景中的数字是练习假设，不是候选人的业务规模。

### 负责人面：从事实到决策

1. 为什么选择 Agent，过去半年为此实际做了什么？
2. 最近亲自做过什么模型实验，结果改变了哪项决策？
3. 哪项个人决策对过去项目结果最关键，有什么证据？
4. 迁移到目标业务时，首先验证哪个风险或假设？
5. 独立负责时，阶段交付、资源取舍和验收指标是什么？

判断依据：实验与行动支持观点，个人贡献可辨认，计划可以验收。知道产品名、表达信心或声称关注热点本身不足以证明能力。

## 题目质量检查

- Token 估算题交代完整调用过程、输入输出与计费假设，不能由“代码行数”推出唯一总成本；示例价格与真实现价分开。
- 检索命中、回答正确、Agent 任务成功和业务验收是不同层次，答案应给各自口径。
- 效果改善要有比较基线和样本来源；准确率、召回率、通过率不互换，目标值不写成实测。
- 恢复题追问外部操作是否已生效与重复执行后果；提到重试或检查点不等于已经解释恢复一致性。
- 高风险操作的控制要落到执行位置和权限边界；模型口头承诺与系统实际约束分开。
- 框架、模型和检索技术都是可选方案，评分依赖场景与解释，不把特定技术名词当作唯一正确答案。
